### (3) 생성형 AI의 매너리즘(반복 피로) 극복: 확률적 도입부와 네이티브 위젯 연계

초기 파이프라인에서는 신비로운 분위기를 연출하기 위해 모든 소설의 서두에 `[도입부 인용 경구]`를 필수로 생성하도록 프롬프트를 구성했습니다:

```

몇 편이 올라갈 때까지는 매우 고급스러워 보였으나, 10편, 20편이 누적되자 치명적인 문제가 드러났습니다:
1. **독자의 피로감과 패턴 간파**: 방문자가 글을 열자마자 "아, 또 인용구로 시작하네"라며 AI가 찍어낸 양산형 글임을 눈치채고 이탈률이 증가했습니다.
2. **서사 시작의 획일화**: 모든 이야기가 정적인 인용구로 시작하다 보니, 급박한 사건이나 인물의 긴장감 넘치는 대화로 치고 나가는 역동적인 서두를 구현할 수 없었습니다.

이를 극복하기 위해 **프롬프트 엔지니어링과 서식 파이프라인을 2단계로 고도화**했습니다:

#### 1) 확률적 서두 다변화 & 인메디아스 레스(In medias res) 도입
* **인용구 빈도 제어**: 매 글마다 기계적으로 인용구를 넣지 않고, **3~4편당 1회꼴(약 25~30% 확률)**로만 엄선하여 고전 인용구를 채택하도록 규칙을 변경했습니다.
* **본문 직결형 서두(In medias res)**: 인용구가 없는 날에는 배경 설명 없이 사건의 한가운데서 이야기를 시작하거나, 인물의 긴박한 대사 한마디, 또는 날카로운 감각적 묘사(바람 소리, 놋쇠 냄새 등)로 독자의 주의를 단숨에 낚아채는 후킹(Hook) 기법을 의무화했습니다.

#### 2) 네이버 스마트에디터 네이티브 '버티컬 라인(quotation_line)' 위젯 연계

#### 1) 문제의 원인
* 스마트에디터 ONE은 본문 전체가 하나의 거대한 `contenteditable`이 아닙니다.
* **제목(`.se-documentTitle`)**, **인용구(`.se-quotation`)**, **본문 1부(`.se-component.se-text`)**, **삽화(`.se-component.se-image`)**, **본문 2부(`.se-component.se-text`)**가 각각 독립된 React 컴포넌트로 완전히 격리되어 있습니다.
* 인용구가 추가되면서 `all_p[1]`은 본문이 아닌 **인용구 텍스트**를 가리키게 되었고, 여기서 `Control+A`를 누르면 오직 인용구 텍스트만 선택되었습니다.
* 설령 본문 1부를 클릭하고 `Control+A`를 누르더라도, **셀렉션 범위가 중간에 삽입된 이미지 블록(`.se-component.se-image`)을 건너뛰지 못해 본문 2부는 서식 적용에서 완전히 소외**되었습니다.

#### 2) 해결책: 컴포넌트 단위 분할 일괄 스타일링(Component-by-Component Batch Styling)
DOM 트리를 순회하여 제목, 인용구, 이미지를 제외한 **순수 본문 텍스트 컴포넌트(`div.se-component.se-text`) 목록만 정밀하게 추출**한 뒤, 각 컴포넌트 블록마다 개별적으로 포커스를 잡고 서식을 주입하는 파이프라인을 구축했습니다:

```python
def apply_post_style(frame, page, style):
    # 인용구, 제목, 이미지를 제외한 실제 본문 텍스트 컴포넌트만 정확히 조회
    text_comps = frame.locator("div.se-component.se-text").all()
    
    font_fam = style.get("font_family", "기본서체")  # system
    font_sz = style.get("font_size", 15)           # fs15
    line_h = style.get("line_height", 180)          # 180%

    for idx, comp in enumerate(text_comps):
        # 컴포넌트 내부 첫 문단 클릭
        p_first = comp.locator("p.se-text-paragraph").first
        p_first.click()
        page.wait_for_timeout(300)

        # 현재 텍스트 블록 전체 선택 (이미지 너머와 섞이지 않는 안전한 블록 셀렉션)
        page.keyboard.press("Control+A")
        page.wait_for_timeout(300)

        # 1. 글자 크기 15pt 적용
        apply_font_size(frame, font_sz)
        # 2. 폰트 서체 '기본서체(system)' 적용
        apply_font_family(frame, font_fam)
        # 3. 줄간격 180% 적용
        apply_line_height(frame, line_h)
        # 4. 좌측 정렬 적용
        apply_align(frame, "left")
```

이 컴포넌트 분할 접근법을 통해, 본문 중간에 몇 장의 삽화나 구분선, 위젯이 끼어들더라도 **소설 본문 전체(1부, 2부, 3부...)의 타이포그래피(기본서체, 15pt, 행간 180%)를 100% 빈틈없이 일괄 통일**할 수 있었습니다.

### 난관 4: 한국어 출판 타이포그래피와 파이썬 `strip()`의 유니코드 공백 삭제 함정

웹소설 및 순수 환상문학의 가독성을 완성하는 핵심 디테일은 **'화자의 대사(대화문)'와 '장면 해설(지문/서술문)'의 시각적 구분**입니다.

1. **대화문(`"..."`)**: 화자의 말이 즉각 튀어나오도록 **들여쓰기 없이(내어쓰기)** 행의 맨 앞에서 시작.
2. **서술문(지문)**: 장면 설명 문단은 고전 출판문학의 규약에 따라 **첫 줄 1칸 들여쓰기**를 의무화.

#### 1) HTML 연속 공백 붕괴와 전각 공백(`\u3000`)의 도입
웹 브라우저의 렌더링 엔진은 문장 첫머리에 일반 스페이스(` `)를 여러 번 넣어도 이를 1칸으로 뭉개거나 아예 무시해버리는 **연속 공백 붕괴(Collapsing Whitespace)** 특성을 지닙니다.
이를 해결하기 위해 한국/동아시아 출판 인쇄 표준인 **전각 공백(IDEOGRAPHIC SPACE, Unicode `\u3000`)**을 도입했습니다. 전각 공백은 웹 브라우저에서도 한글 한 글자(1em)와 정확히 동일한 가로 폭을 영구히 유지하며 들여쓰기를 만들어 줍니다.

정규식을 통해 대화문과 서술문을 자동 분리하고, 서술문의 첫머리에 `\u3000`을 자동으로 주입하는 전처리기를 만들었습니다:
```python
def apply_indent_to_narrative(text: str) -> str:
    paragraphs = []
    for p in text.split("\n\n"):
        p_clean = p.strip(" \t\r\n")
        # 따옴표로 시작하지 않는 서술문인 경우 전각 공백 1칸 삽입
        if not p_clean.startswith(('"', '“', '「', '『')):
            if not p_clean.startswith('\u3000'):
                p_clean = '\u3000' + p_clean
        paragraphs.append(p_clean)
    return "\n\n".join(paragraphs)
```

#### 2) 파이썬 `str.strip()`의 복병: "왜 블로그에 올라가면 들여쓰기가 사라지지?"
원고 파일(`20-xxx.md`)을 직접 열어보면 분명히 서술문마다 `\u3000`이 단정하게 박혀 있었습니다. 하지만 Playwright가 스마트에디터에 타이핑을 마치고 발행된 포스팅을 보면 **모든 들여쓰기가 온데간데없이 사라지는 기현상**이 발생했습니다.

원인은 놀랍게도 파이썬 표준 라이브러리의 구현 방식에 있었습니다:
```python
# naver_publisher.py의 본문 타이핑 루프
for paragraph in body_part1.split("\n"):
    line = paragraph.strip()  # <--- 문제의 원흉!
    page.keyboard.insert_text(line)
```

파이썬의 `str.strip()`은 인자 없이 호출할 경우 단순히 아스키 공백(`\x20`, `\t`, `\n`)만 제거하는 것이 아니라, **유니코드 공백 카테고리(`Zs`)에 속하는 모든 문자**를 공백으로 간주하여 잘라냅니다.
* `unicodedata.category('\u3000') == 'Zs'`
* 결과: `'\u3000지상의 도시들이...'.strip() == '지상의 도시들이...'`

문자열을 정제하려는 순수한 의도로 넣었던 `paragraph.strip()` 한 줄이, 기껏 삽입해 둔 **전각 공백 들여쓰기를 타이핑 직전에 모조리 증발**시키고 있었던 것입니다.

#### 3) 해결책: 명시적 화이트스페이스 경계 지정
파이썬 기본 `strip()`을 걷어내고, 아스키 공백과 개행만을 명시적으로 지정하여 전각 공백을 안전하게 보호하도록 수정했습니다:
```python
# [개선 전] 유니코드 전각 공백까지 공백으로 취급하여 잘라버림
line = paragraph.strip()

# [개선 후] 아스키 띄어쓰기, 탭, 개행만 정리하고 전각 공백(\u3000)은 온전히 보존
line = paragraph.strip(" \t\r\n")
```

이 디버깅을 거친 후, 발행된 블로그의 모든 본문에서 **"따옴표 대사는 벽에 붙어 시작하고, 서술문은 한 글자 단정하게 들어가며, 두 요소 사이에는 여백이 흐르는"** 고품격 출판 타이포그래피를 100% 자동화로 재현할 수 있었습니다.
```

## 4. 이직 및 테크 면접 대비: 트러블슈팅 1분 스피치 키포인트

> 기술 면접에서 *"프로젝트를 진행하면서 가장 예상치 못했던 기술적 문제와 해결 경험은 무엇인가요?"*라는 질문을 받았을 때, 아래의 스토리라인으로 답변하면 기술적 깊이와 문제 해결 태도를 완벽하게 어필할 수 있습니다.

### 🎙️ 1분 면접 답변 템플릿

> "네이버 스마트에디터 자동 발행 파이프라인을 구축하면서 가장 흥미로웠던 문제는 **'복합 컴포넌트의 DOM 셀렉션 격리'**와 **'파이썬 유니코드와 웹 타이포그래피의 충돌'**이었습니다.
> 
> 첫째로, 스마트에디터 ONE은 인용구, 본문 텍스트, 삽화 이미지가 각각 독립된 React 블록 컴포넌트로 분리되어 있었습니다. 일반적인 `Control+A`는 현재 블록에만 갇혀 중간의 이미지를 건너뛰지 못했습니다. 이를 해결하기 위해 에디터 내부의 모든 텍스트 컴포넌트(`se-component.se-text`)를 쿼리하여 블록 단위로 순회 스타일링을 적용하는 분할 제어 패턴을 구현했습니다.
> 
> 둘째로, 고전 소설의 가독성을 위해 웹에서 연속 공백이 축소되는 한계를 극복하고자 유니코드 전각 공백(`\u3000`)으로 첫 줄 들여쓰기를 구현했습니다. 그런데 스크립트를 거치면 들여쓰기가 감쪽같이 사라졌습니다. 역공학을 진행해 보니 파이썬의 표준 `str.strip()`이 유니코드 `Zs` 카테고리까지 공백으로 인식해 전각 공백을 잘라내고 있었습니다. 이를 `strip(' \t\r\n')`으로 명시적 화이트스페이스만 정제하도록 방어 코드를 작성하여 해결했습니다.
> 
> 이 경험을 통해 **단순히 라이브러리를 쓰는 수준을 넘어, 웹 에디터 프레임워크의 DOM 아키텍처와 프로그래밍 언어의 유니코드 표준 스펙을 깊이 있게 이해하고 디버깅하는 엔지니어링의 중요성**을 배웠습니다."
